## Limitations and interpretation warnings

- Each arm differs from its comparison arm by a bundle of design features (for C−A and D−B: hierarchical tree vs one flat layer, depth, weight sharing, width, parameter count and compute). A difference is attributable to the bundle as implemented, not to any single feature such as 'hierarchy'.
- C−B changes both architecture and normalisation; it is descriptive only and supports no inference.
- All conclusions are conditional on the selected learning rate (0.03 for every arm, coarse grid, D-22), the common 26-epoch budget (D-32), plain SGD with batch size 32, this dataset and split, and CPU float32.
- Confidence intervals are nominal 95% per comparison, not simultaneous; Holm adjusts only the paired t-test p-values within each declared family. Sign-flip p-values are a separate sensitivity analysis.
- With n paired seeds the exact sign-flip test cannot go below 2/2^n; seeds measure initialisation and data-order variability only, not variability over datasets or hyperparameters.
- Dev NLL was used for learning-rate, budget and checkpoint selection, so best dev NLL is optimistically biased; it is descriptive only. Test NLL was evaluated once per run after the freeze.
- Context-stratified results are exploratory: definitions were fixed on dev data, test support may be small, categories are not crossed, and no inferential adjustment is made across categories.
- SESOI = 0.01 nats per character is a chosen practical convention, not an empirically derived threshold.
- Runtime figures describe this hardware, thread setting and measurement protocol only; no inferential efficiency claim is made.
